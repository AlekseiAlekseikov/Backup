## 2. Как работает (кратко)

1. **Клик тумблера** (`AppPerformance` → `JitMechAndroid.click` → `JitMech.click`, как `j9.onClick`): флаг busy;
   читается `isWifiEnabled`; в ОБА хранилища префов пишутся `jit_pedido=X`, `perf_auto_otimizar=X`,
   `jit_restaurar="wifi=0|1"`; лог `dalvik.vm.usejit -> X; reiniciando o framework`; цепочка уходит одной командой в пул
   (BgWorker). Единственный отказ — `busy` (WARN). Ни фаз, ни TTL-снимков, ни PID, ни «лечения» перезагрузкой.
2. **Цепочка** — литерал `la.run` из DEX байт-в-байт (392 символа сырого литерала / 298 после `trimIndent`):
   `svc wifi disable` → дренаж `ip rule show | grep -c 'oif wlan0'` до 0 (≤ 20 × `sleep 1`) → `umount -l` по точкам
   `/data/app/` из `/proc/mounts` → `setprop dalvik.vm.usejit true|false` → `setprop ctl.restart zygote` (последней, один раз).
   Kotlin-пример промпта содержит ошибки — взят литерал DEX (см. сравнение).
3. **Возврат Wi-Fi** — `JitWatchdogService` (аналог `CentralWatchdogService`), стартует при старте процесса и из
   BootReceiver; при недоступности сервиса — тот же код inline. `jit_restaurar` ↔ `^wifi=([01])$` (хвост `,ap=Y` от
   формата референса принимается и игнорируется; AP не трогаем); ключ удаляется сразу (one-shot); через 15 с, если
   `wifi=1` и Wi-Fi выключен — `setWifiEnabled(true)`; лог `JIT: restaurado após o restart (wifi=X); wifi agora=...`.
   Неверный формат — ключ не трогается (как в DEX).
4. **Сверка** (`bb/r7`): `getprop dalvik.vm.usejit` (таймаут 8 с) + `/proc/self/maps` (строки `jit-cache`/`dalvik-jit-code-cache`,
   права `r-xp/rwxp/r-xs/rwxs` → true, только `rw-p` → false, строк нет → null);
   `ok = (pedido == getprop) && (!pedido || maps != false)` → OK / CACHE_MISSING / NOT_APPLIED; `jit_pedido` снимается.
   Тумблер рисуется по ФАКТУ getprop. Тост `master_perf_jit_not_applied` заменён подсказкой в существующей строке
   состояния (без новых кнопок и красных текстов).
5. **Нет** авто-применения на загрузке, persist-свойств JIT, `jit_boot_restore_done`, библиотеки claim.
   `ctl.restart zygote` — только из клика.

## 5. Что сделано иначе, чем у референса (тот же результат)

Подробно с цитатами DEX — `docs/agent/JIT_COMPARISON_1.0.65.md`. Кратко:
- `jit_restaurar = "wifi=X"` без `ap=` (AP приложение не трогает); `,ap=Y` при чтении принимается и игнорируется.
- Префы пишутся в оба хранилища (DPS и CPS), как и раньше у 1.0.64.
- Нет диалога подтверждения, прогресс-диалога и 45-секундной очистки — запрет новых элементов UI; busy снимается по ответу цепочки.
- Тост not_applied → подсказка в существующей строке состояния тумблера.
- Сверка откладывается, если getprop не прочитан, и пропускается, пока клик в полёте (ключ `jit_pedido` не теряется).
- TTL-снимки и read-only диагностика JIT оставлены (принятые функции).
