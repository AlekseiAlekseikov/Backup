### 1.2 Что исправлено (production-путь)

* `LockOp.reconStep` переписан по §3.2. Порядок решения: **terminal BIND → terminal ПРЕЖНЕЙ
  попытки → (read-only: наблюдение) → подготовка identity → отправка → исход → сверка целей**.
  `Unknown` новой попытки не разрешается terminal'ом старой (`LockOp.kt:418–560`).
* `LockOp.ReconPorts`: `restore(op, attempt: String)` — отправляется ровно записанный путь;
  `prepareRestore` обязан вернуть непустую identity; добавлены `readOnly()` и `observe(op)`.
* `LockSound.appendOp` подтверждает запись через `LockOp.sameIdentity` (id/state/gen/stage/
  targets/evidence/restoreEv/reason) — stale-копия больше не затирает адрес свидетельства.
* `LockSound.prepareRestore`: кандидат `op.copy(restoreEv=…)` пишется ДО отправки; не подтвердили
  чтением — отправки нет вообще.
* `LockMountScripts.observeScript` (новый, ~40 строк): **чисто читающий** скрипт состояния целей —
  `STOCK_OK` / `OWN_PROOF` / `FOREIGN_MOUNT` / `STOCK_UNPROVEN`; ни `mount`, ни `umount`, ни записи
  файлов. Им read-only проход закрывает операцию по факту, а не «висит вечно».
* Поведение iter58, изменённое осознанно: **restore при недоказанном terminal bind больше не
  отправляется**. Два старых теста (`Iter57SoundTest`, `Iter58SoundTest`) обновлены: их ожидание
  «restore всё равно уходит» прямо противоречило требованию §3.2.5.

* 🟡 Реальные `mount`/`umount` в прошивке ГУ: скрипты исполнялись настоящим `/bin/sh` на
  подставной таблице монтирований (`MOUNTINFO`), а не на устройстве.

## 2. JIT (§5): admin-секция без «compare-and-unlink»

### 2.1 Дефект подтверждён

`JitOwn.kt:461–465` (iter58): «прочитать → доказать смерть → сравнить → `rm -f` по ИМЕНИ».
`Iter59JitAdminTest.iter58CompareAndUnlinkRemovesALiveAdminAndLetsTwoOwnersIn` воспроизводит это
**настоящими процессами `/bin/sh` с барьерами** ровно между финальным сравнением и `rm`:

```
B читает мёртвую строку → доказал смерть → сравнил (C_COMPARE=same) → снял имя → поставил СВОЮ
C (его rm приготовлен ДО появления живого B) → удаляет admin ЖИВОГО B
assert: admin с inst=B больше не существует, B при этом жив  ⇒ взаимное исключение разрушено
```

Тест зелёный — то есть дефект был реальным interleaving'ом кода, а не гипотезой.

### 2.2 Что сделано

`JitOwn.kt` (блок admin-секции переписан):

* общий файл `<lock>.admin` заменён каталогом `<lock>.adm` с **уникальными** записями участников
  `p.<inst>.<pid>`, появляющимися атомарно (`temp` + `ln`: имя возникает сразу с содержимым);
* вход — «билеты»: `ticket = 1 + max(видимых)`, равные тикеты разбираются именем; входит только
  тот, для кого нет **живого** участника с меньшим ключом `(тикет, имя)`;
* чужую запись можно снять **только по её собственному уникальному имени** и только после
  доказанной смерти (`_jit_death_proven`: свой END / другая загрузка / нет `/proc/<pid>` /
  переиспользован pid) ⇒ «удалить admin живого владельца» невозможно **по построению**;
* legacy `<lock>.admin`: доказанно мёртвый переносится в уникальное имя с проверкой перенесённого
  содержимого (ошибка только в сторону лишней блокировки); живой — блокирует и не трогается;
* отказ вместо вечной блокировки: если смерть доказать нечем, вход не происходит, своя запись не
  остаётся (проверено `corruptParticipantEntryIsNeverRemovedWithoutProofOfDeath`);
* `_lock_self_mark`: результат ОБЯЗАН подтверждаться чтением lock, при неудаче прежняя строка
  возвращается, функция отдаёт ошибку, а `guard` по ней делает `_refuse self_mark_failed` **до**
  опасного действия. Раньше вызов глушился `2>/dev/null` и rc игнорировался (`JitOwn.kt:1101`).

Доказательства (реальные процессы, реальный `/proc`, настоящая сигнализация):

| Тест | Что доказывает |
|---|---|
| `newProtocolKeepsTheLiveParticipantAndRefusesTheSecond` | живой участник не удаляется, вход запрещён, утечки записи нет |
| `concurrentParticipantsNeverHoldTheSectionTogether` | 4 процесса × 15 входов: «свидетель» ни разу не занят дважды; 0 нарушений, 60 фактических входов |
| `deadParticipantIsReclaimedByItsOwnNameOnly` | crash-release по своему имени; своя запись снимается на выходе |
| `killedParticipantInsideSectionDoesNotBlockForever` | SIGKILL внутри секции: следующий вход состоялся, ожидание ограничено |
| `legacyAdminFileIsMigratedWhenDeadAndKeptWhenLive` | миграция мёртвого legacy-файла; живой не тронут |
| `guardRefusesWhenSelfMarkCannotBeEstablished` | отказ стоит ДО `START`, общего `rm` по имени нет |

### 2.3 Границы

* 🟡 Всё проверено на Linux `/bin/sh` + `/proc` песочницы, не на Android/toybox ГУ. Используемые
  примитивы (`mkdir`, `ln`, `read`, `mv`, `rm`, `/proc/<pid>/stat`, `sleep 0.01`) в toybox есть,
  но фактическая семантика прошивки не проверялась.
* 🟡 `flock`/`renameat2`/`stat -c` НЕ предполагаются: протокол на них не опирается.
* 🟡 Миграция legacy-файла имеет узкое окно (доказали смерть → `mv`): если ровно в этот момент
  legacy-процесс прежней версии создаст новый файл, перенесён может быть он. Ошибка направлена в
  сторону «лишняя блокировка» (файл возвращается), но окно существует; после обновления legacy
  процессов не остаётся.
* ❌ `seq/epoch` (§5.3) в этом проходе НЕ переделывались: `JitNet.kt` не менялся. Требование «не
  возвращать `seq_owner_ended`» выполнено (ветки нет), но межпроцессная нумерация с учётом epoch
  и восстановление после сброса данных не реализованы. Это отдельная работа.

## 3. TTL (§6)

### 3.1 Исправлено

* `TtlScript.ownmark_ok <v4|v6>`: владение доказывается **по семейству** — нужна строка
  `v4=created`/`v6=created` И существование цепи, прочитанное ТЕМ ЖЕ инструментом. Раньше проверка
  всегда читала v4, поэтому своя v4-цепь «доказывала» и одноимённую **чужую** v6.
* `NAMED_OWN_V4`/`NAMED_OWN_V6` вместо одного общего флага; `chain_state` берёт флаг того
  семейства, чью таблицу читает.
* Отказ записи маркера v6 теперь симметричен v4: проход останавливается, правила снимаются,
  `chain_delete_rc` **учитывается и печатается**; создание v6-цепи при отсутствии файла маркера
  тоже откатывается.
* `TtlAttempt` (новый): durable identity попытки (`write` + readback **до** отправки) и правило
  повтора.
* `NetworkTtl`: `prepare → recordAttempt → executePrepared`; повтор — **только** при доказанном
  `Finished` + `no_uplink`; каждая повторная попытка получает СВОЮ identity; `Unknown` больше не
  повторяется (мутация не может выполниться дважды). `Pair`-retry удалён.
* Потребитель берёт код payload (`payloadRc`), код канала логируется отдельно.
* CarPlay-правила и раздача не трогались (фильтр `p2p*/rndis*/ncm*/usb*/ap0*` сохранён).

Доказательства: `Iter59TtlTest` — чужая v6 не становится своей (ни одного мутирующего argv по
v6-цепи, `TTL_OWN family=v6 … action=keep`), независимое решение семейств, несохранённый маркер v6
снимает цепь и печатает rc, durable identity + правило повтора (RETRY только после `no_uplink`).

### 3.2 Не доказано

* 🟡 Реальные `iptables`/`ip6tables` ГУ и фактический TTL в тракте — не проверялись. Тесты
  используют подставные `iptables`/`ip6tables` со строгой проверкой argv и настоящей таблицей.
* 🟡 «Интернет после включения TTL» (DNS + реальная страница) не проверялся: в песочнице нет
  устройства. Требование §6.3 «страница/DNS/маршрут — отдельный протокол» остаётся нереализованным.
* ❌ `NetworkTtl` в JVM-стенде не компилируется (Android API), поэтому его правки проверены только
  `typecheck_lock.sh` + тестами на `TtlAttempt`/`ScriptDelivery`, а не исполнением.

## 4. Доставка (§7)

* `ScriptDelivery.Result`: добавлены `transportRc`, `payloadRc` (`RC_UNKNOWN` = не доказан),
  `rcFromDone`. Причина: при потере ответа код ТРАНСПОРТА попадал в `rc` и был неотличим от кода
  скрипта.
* `directResult`: код маркера этой попытки → `payloadRc`; без маркера — `RC_UNKNOWN`.
* `deliver`: `SCRIPT_RUN_DONE` → `payloadRc`; durable `<path>.done` → `payloadRc` + `rcFromDone`.
* `outcome()` отдаёт наружу код payload; `LockSound` и `NetworkTtl` используют `payloadRc`.
* Коллизия имени (iter58 фикс) сохранена и покрыта тестом: занятое имя не перезаписывается,
  создание только в noclobber-режиме, берётся новый nonce, в занятое имя никто не пишет.

Фикс rc iter58 (`_VRC=$?` до `echo`) не тронут — регрессии `Iter58DeliveryRcTest` зелёные.

🟡 Все тесты доставки идут на подставном транспорте/настоящем `/bin/sh` в песочнице; реальный
ADB-канал ГУ не проверялся.
