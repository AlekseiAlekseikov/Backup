## Центральное архитектурное открытие (по декомпиляции)

**CentralEXAuto вообще не использует Runtime.exec("sh") как способ получить root.** Это главное расхождение с нашим кодом.

Цепочка в оригинале (из `w0/m.l()` и `w0/n.case 0`):

```
m.l()  →  m.y(8000, SCRIPT)  →  m.x(SCRIPT, 8000, null, new n(0))
                                          │
                                          └── n(0).b(SCRIPT, 8000):
                                                if (m.f3919a != 0) → new h(m.f3919a /* port */).b(SCRIPT)
                                                for port in {65010, 5555}:
                                                    try new h(port).b(SCRIPT); m.f3919a=port; return
```

`kotlinx.coroutines.scheduling.h` (псевдоним нашего AdbClient) — это ADB-сокет клиент, который подключается к `127.0.0.1:PORT` и отправляет `shell:<script>` по ADB-протоколу. **Важно: и сам скрипт миграции порта (`setprop persist/service.adb.tcp.port=65010; (sleep 1; setprop ctl.restart adbd)&`) запускается через уже работающий ADB-сокет на 5555** (первая итерация n.case 0 использует кэшированный m.f3919a, если 0 — пробует 65010 потом 5555). Значит, на ГУ adbd на 5555:
1. Уже запущен из коробки (либо поднимается раньше приложения);
2. Работает в режиме root (навигация/system app на ECarX это типично);
3. Не требует RSA-аутентификации для локальных подключений.

У нас в коде:
1. `ensurePortMigrated()` вызывает setprop/ctl.restart через `Runtime.exec("sh")` от uid=1000 — SELinux не даёт писать в `ctl.*` свойства → `ctl.restart adbd` не срабатывает → adbd никогда не переезжает на 65010.
2. `execute()` сначала вызывает `ensurePortMigrated()` (который 9 секунд ждёт несуществующий порт), потом пробует ADB-сокет на 65010 (не слушает), на 5555 (требует AUTH или не слушает на localhost), потом падает в `sh -c` от uid=1000 без рута.

Поэтому первопричина всех проблем — **запуск скрипта миграции через `Runtime.sh` вместо ADB-сокета**. Наш `AdbClient` должен в точности повторить логику `n(0)`: при первом вызове в фоне попробовать ADB на 5555 (короткий таймаут); через этот канал запустить скрипт миграции (setprop+ctl.restart); затем дождаться прослушивания 65010 и перейти на него. Если 5555 не работает — запустить диагностику (AUTH? refused? timeout?) и дать внятную ошибку, а не падать молча в Runtime.sh.

## Оставшиеся блокеры / что не видно из лога

1. **Доступность su на ГУ вообще** — лог показывает только uid=1000(system), но не показывает результат `su -c id` и `adb shell getenforce` и `netstat -ltnp`. Требуется команда с ГУ до окончательной починки порта. Код напишу с упором на ADB-сокет (по оригиналу), так как su может не быть.
2. **Точные propId для SOC и ext-temp** — сейчас код спрашивает 0x16400b00 area=0 / 0x16400c00 area=0 по `w0/a3`, но в логе это всё равно даёт 36/-22, что говорит о том, что либо areaId в реальности другой, либо свойство 0x16400b00 на этом ГУ не заряд батареи. Нужно проверить через `VhalProviderService` (как в оригинале `rg.p`/`rg.d`), либо через чтение пропов плагина `persist.sys.hvacdigital.*` как рабочего источника.

## ХОД РАБОТ (по состоянию на 2026-10-28)

### ✅ Сделано

- **P2 (screen_off_timeout vandalism)** — Полностью удалён код, писавший `2147483647`. Удалён 30-секундный watchdog-переустановщик. Приложение НИКОГДА автоматически не пишет в `SCREEN_OFF_TIMEOUT`. При первом старте читается текущее значение; если оно `Int.MAX_VALUE` (остаток предыдущей версии) — в лог выводится явная просьба пользователю выставить таймаут вручную в Настройки → Экран → Спящий режим; после этого значение больше не трогается. **Заводское значение не захардкожено** — уточним по дампу прошивки.
- **P1 (main-thread ban)** — Добавлен `tools/BgWorker.kt` (пул из 4 daemon-потоков `CENTRAL_Bg`, post/run с доставкой результата на main Handler, assertNotMain для дебага). `AdbClient.execute()` теперь жёстко детектирует вызов с main (stacktrace с точным file:line вызывающего), не блокирует UI (ставит в очередь и возвращает `ERR_MAIN_THREAD_FORBIDDEN`), добавлен `AdbClient.submit()`. Все точки входа с главного потока (UiBridge.onEvent, VoiceAssistantService onStartCommand/watchdog/BroadcastReceiver, StatusIcons 15-с тик, onAppResumed) завернуты в `BgWorker`. В blocking-методы добавлены `BgWorker.assertNotMain()` guards (NetworkTtl, StatusIcons, AppPerformance.runSuCommand, ScreenBrightness.writeSysfs/writeProp, LockSound.onBootOrWatchdog).
- **P4 (TTL)** — Все вызовы iptables/ip6tables снабжены `-w 5` (wait for xtables lock). Добавлены `TTL_BEFORE_*`, `VERIFY_V4/V6=OK/FAIL/ABSENT/PRESENT` (через `iptables -C`). Строгая проверка результата в `setTtl65Active`: `exitCode=0` сам по себе не SUCCESS; детектируются `xtables lock` / `Permission denied` / несовпадение счётчиков; VERIFY-строка в логе в формате `expected … → got … → SUCCESS/FAILED`.
- **P5/P6 perf setenforce** — Удалён `setenforce 0` из HvacDigitalPlugin, AppPerformance.setVideo60Fps и LockSound (оставлен только `getenforce` в логах SELINUX_BEFORE/AFTER). bind-mount остаётся; позже добавится полная inode-верификация и проверка рестарта конкретных сервисов (медиа/zygote).
- **AdbClient bootstrap (P0 часть)** — Скелет уже делает bootstrap в AdbWorker потоке, пробует порты 65010/5555, выполняет migrate-скрипт через ADB-сокет (а не Runtime.sh), ждёт прослушивания 65010, логирует по шагам PORT65010. Падение в NO_ROOT_SH с явной причиной.

### 🚧 Осталось сделать (блокеры)

- **P0 uid=0 верификация**: `AdbClient.runCommand()` пока просто возвращает вывод и не проверяет, что первая строка от `id` содержит `uid=0(root)`; после пробы порта не различает ROOT_5555 vs NO_ROOT_SH детерминированно, и фоллбэк-Runtime.sh всё ещё может маскироваться под успех. Нужно жёстко: uid!=0 + 5555 reachable → NO_ROOT_SH с явным сообщением; root команды не вызывать без uid=0.
- **P3 batt/temp источник**: сейчас StatusIcons.syncAll всё ещё использует VHAL с brute-force areaId. Нужно сделать single-source: читать `persist.sys.hvacdigital.*` те же пропы, что использует плагин «Строка состояния» — с тем, чтобы при работающем плагине значения брались из него, а VHAL fallback использовать только как вторую очередь с явной проверкой диапазона (SOC 0..100, temp -40..60) и логом `soc=74 (src=hvacdigital_prop)` / `src=VHAL:0x16400b00`.
- **P5 perf полная верификация**: `mount -o bind` и VERIFY по `SRC_INODE==TGT_INODE` + проверка присутствия в `/proc/mounts`; убрать `svc wifi disable`; верифицировать рестарт zygote (pid change + `getprop dalvik.vm.usejit`); фейковый SUCCESS при FAILBIND запретить.
- **P6 JIT**: verify `getprop dalvik.vm.usejit` после скрипта; пиды zygote до/после; не ломать Wi-Fi.
